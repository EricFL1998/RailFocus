# Rail Focus 真实同车旅客（真实在线·路段匹配）设计方案

## 1. 核心定位与原则

### 一、 核心原则：100% 纯真实，零虚假数据
- **绝不使用算法伪造或模拟虚假人数**：没有其他用户就真实展示 0（或仅提示自身），有则真实展示；
- **同路段动态交集匹配**：不仅是起终点完全一致才算同车；只要其他用户的旅程在**同一物理路段/同一车站区间**发生时空重叠，即视为“同车次旅客”；
- **途径站真实上下车感知**：列车每驶入/驶出一个车站，根据真实其他用户的开始与结束，提示“XX站有 X 位旅客上车/下车”；
- **终点站真实纪念面板**：旅程结束后，展示在本次专注全程中，与你曾经“同乘并肩专注”过的真实旅客总数及各区间相遇记录；
- **零成本方案（0 元运营）**：利用永久免费的 Serverless 基础设施（如 Supabase 免费层），无需购买任何云服务器。

## 2. 真实路段匹配与上下车判定逻辑

### 一、 什么是“同车乘客”（区间交集算法）
高铁上旅客的起终点各不相同，但在同一个物理区间内共处一列车。
例如：
- 用户 A：**北京南 → 上海虹桥**（途经济南西、南京南）
- 用户 B：**济南西 → 南京南**

当列车运行到 **济南西 → 南京南** 这个区间且两人同时处于专注状态时，用户 A 和 用户 B 即互为**同车乘客**。

```
时间轴与路线覆盖：
用户 A: [北京南] ───────> [济南西] ═══════════════> [南京南] ───────> [上海虹桥]
用户 B:                    [济南西] ═══════════════> [南京南]
                                  ▲               ▲
                                  │               │
                            用户B在济南西上车   用户B在南京南下车
                          （A提示: 济南西 1人上车）（A提示: 南京南 1人下车）
```

- **500 MB 数据库存储**（仅存临时心跳记录，单表占用极小）。

### 一、 极简数据表设计（单表完成全部匹配）

```sql
-- 活跃专注旅客心跳表（专注结束或超时自动视为下车）
CREATE TABLE active_journeys (
    id UUID PRIMARY KEY,                   -- 旅程唯一 ID
    user_identifier TEXT NOT NULL,         -- 匿名化设备指纹/随机用户 ID
    seat_info TEXT NOT NULL,               -- 分配的座位（如 05车08A）
    start_station_name TEXT NOT NULL,      -- 该旅客旅程的始发站（如 "北京南"）
    end_station_name TEXT NOT NULL,        -- 该旅客旅程的终点站（如 "上海虹桥"）
    focus_type TEXT NOT NULL DEFAULT '通用',-- 专注类别（如 "深度工作"、"考研自习"、"阅读"）
    station_ids TEXT[] NOT NULL,           -- 本次旅程规划经过的所有站点 ID 数组
    current_segment_from TEXT NOT NULL,    -- 当前所在区间的出发站 ID
    current_segment_to TEXT NOT NULL,      -- 当前所在区间的下一站 ID
    current_segment_index INT NOT NULL,    -- 当前在第几段区间
    status TEXT NOT NULL DEFAULT 'RUNNING',-- RUNNING / PAUSED / COMPLETED
    started_at TIMESTAMPTZ NOT NULL,       -- 开始时间
    last_heartbeat TIMESTAMPTZ NOT NULL DEFAULT NOW() -- 心跳保活时间
);

-- 为当前区间建立索引，实现毫秒级路段交集查询
CREATE INDEX idx_active_segment ON active_journeys (current_segment_from, current_segment_to);
```

### 二、 客户端心跳与状态同步（极低流量）
1. **发车（进入专注）**：
   - 上报 `active_journeys`，写入自身路线站点数组及起点区间。
2. **行驶中（轻量保活心跳）**：
   - 每 45 秒或每次列车到达下一区段时，更新一次心跳与当前区间 (`current_segment_from`, `current_segment_to`)；
   - 查询当前正在同一区间专注的真实人数：
     ```sql
     SELECT id, seat_info, start_station_name, end_station_name, focus_type, started_at
     FROM active_journeys 
     WHERE current_segment_from = :currentFrom 
       AND current_segment_to = :currentTo
       AND id != :myJourneyId
       AND last_heartbeat > NOW() - INTERVAL '90 seconds';
     ```
3. **靠站/到站（触发上下车事件）**：
   - 到达新车站时，比对上一区间的同乘列表与当前区间的同乘列表；
   - 新增的乘客触发：**“【XX站】有 1 位旅客上车”**；
   - 离开的乘客触发：**“【XX站】有 1 位旅客下车”**。
4. **终点到站 / 取消**：
   - 旅程状态标记为 `COMPLETED` 并退出心跳；
   - 超过 90 秒无心跳的异常中断设备自动被服务端过滤，保证人数绝不虚标。

## 4. UI 界面与交互设计

### 一、 专注进行中：车厢实时客流屏与同乘旅客列表

1. **常驻微型状态标**
   - **位置**：专注界面右上角或控制区旁的微型胶囊标。
   - **状态展示**：
     - **当前无人同乘**：展示 `[ 💺 独自前行 ]`；
     - **有真实同乘**：展示 `[ 💺 同车旅客 2 人 ]`。

2. **【同车旅客列表】极简抽屉（点击展开）**
   - 点击状态标自底部滑出极度纯净的同乘旅客卡片列表。
   - **严格遵循极简与隐私原则：仅展示三项核心信息，其余一概不展示**：
     - **始发站 ➔ 终点站**：例如 `北京南 ➔ 上海虹桥`
     - **专注类别**：例如 `深度工作`、`背单词`、`考研自习`
   - **卡片原型示意**：
     ┌──────────────────────────────────────────────┐
     │  北京南 ➔ 上海虹桥            [ 深度工作 ]    │
     └──────────────────────────────────────────────┘
   - **零多余元素**：不展示用户名、不展示头像、不展示座位号、不展示在途时长，杜绝任何窥探感与社交压力。

### 二、 到站时动态：真实上下车微播报
- 当列车行驶到某一个中间车站时，若检测到真实用户变动，在车站信息卡上方弹出轻量文字吐司（Toast/Banner）：
  - 🟢 *“列车到达徐州东站，有 1 位旅客上车与你同行”*
  - ⚪ *“列车离开蚌埠南站，同乘旅客在蚌埠南站下车”*

### 三、 旅程结束：真实同乘纪念面板
- 倒计时结束、到达终点站后，在 `CompletionOverlay` 完成面板底部增加**【同乘旅行纪念】**专属卡片：
  - **文案**：
    - 若全程独自一人：*“本次旅程由你一人安静包车完成，享受了难得的专属专注时光”*；
    - 若有真实同行者：*“本次旅程全程共有 3 位真实旅客曾与你在不同路段并肩专注，最长同行 42 分钟”*；
  - **相遇记录清单（严格仅保留三项信息）**：
    - `北京南 ➔ 杭州东 · [深度工作]`
    - `济南西 ➔ 南京南 · [英语背词]`
