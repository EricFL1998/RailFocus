# Rail Focus 旅程手账与“那年今日”功能设计方案

## 1. 功能概述与核心价值

本功能旨在将用户的“单次专注完成”升级为具有持久情感价值的“铁道旅行记忆”。

在一次旅程顺利结束（正点到达或到站）后，用户可在完成面板上点击**“记手账”**，为本趟旅程添加文字感悟与照片插图，系统自动打上精确的时空时间戳（乘车日期、具体到达时间、车站及车次）。

当用户在未来的某一天（或若干个月、一年后）再次选择、经过或到达该车站时，系统将智能唤醒这段沉淀的记忆，触发**“那年今日 · 车站旧忆”**，带来穿越时空般的温暖旅行体验。

---

## 2. 核心用户旅程与交互设计

```
[旅程完成/到站] 
       │
       ▼
[完成面板 (即时唯一入口)] ──点击──> [手账编辑器 (撰写文字 / 上传图片)] 
                                         │ 保存
                                         ▼
                               [本地持久化 (时空时间戳)]
                                         │
                   ┌─────────────────────┴─────────────────────┐
                   ▼                                           ▼
         [再次抵达/途径该站]                         [历史车票/票夹回顾]
                   │                                           │
                   ▼                                           ▼
       [“那年今日”弹窗/飘带提示]                      [车票背后翻转查看手账图文]
```

### 一、 发起入口与编辑流程（写手账）

1. **入口呈现（即时专属）**
   - **完成面板（CompletionOverlay）专属入口**：仅在专注完成靠站的当下，在完成面板操作区提供唯一的记录入口：`[ ✍ 记录旅行手账 ]`。
   - **当下即刻记录原则**：手账为当次到站的专属即时体验，事后历史车票只用于翻转回顾与长图分享，不提供“事后补记”入口，以保持当下专注结束时最真实心境的仪式感与不可逆性。
2. **手账编辑界面设计**
   - **头部时空标签（自动锁定）**：展示只读车次、出发地与目的地、精确到达时间戳（如：`2026年9月21日 15:30 抵达 南京南站 · G124次`）。
   - **文字心得输入区**：大字号清新便签纸风格输入框，支持多行输入（可预留轻量占位文字：“记录下此刻的心情或专注成果吧…”）。
   - **配图插画/照片插入**：
     - 支持调用系统相册选取 1~3 张照片（或拍摄一张当前工作台/窗外风景）；
     - 支持选择系统内置的复古旅行贴纸（如“车站印章贴纸”、“咖啡杯”、“书籍”）。
   - **时间胶囊封存交互**：点击“封存手账”时，伴随一枚虚拟火漆印章或邮戳盖印的小音效与轻触震动，优雅关闭并保存。

---

### 二、 那年今日（旧地重游）唤醒机制

1. **触发时机与判定条件**
   - **场景 A：选定终点站时**（发车前触发轻提醒）：
     - 当用户在路线选择中选中了过去曾写过手账的车站作为目的地时，在车次详情或站点卡片下方浮出轻量温情横幅：“你曾在 1 年前的今天在这里留下过一段回忆”。
   - **场景 B：旅程结束靠站时**（到站深度唤醒）：
     - 当本次专注完成、列车滑行驶入该车站时，完成面板弹出专属的**【那年今日 · 旧地重游】**回忆卡片。
2. **时间跨度算法与优先级**
   - **同月同日（真·那年今日）**：优先展示整一年前、两年前同一日期（±3 天窗口期）在该站写下的手账。
   - **季节记忆（那季今日）**：若无同月同日记录，退化为展示上一次抵达该站时的历史手账（例如：“180天前，你曾在此专注工作了 60 分钟…”）。
3. **展示形式**
   - **拍立得/时光明信片卡片**：微微泛黄的质感纸张，顶部展示当年的照片与手写体文字，底部标注“写于 2025年09月21日 南京南站”。
   - **今昔对比**：下方引导“在今天写下新的手账”，形成不同年份在同一个车站的时间轴叠放（Timeline）。

---

### 三、 历史票夹与长图分享（查手账）

1. **车票 3D 翻转效果**：
   - 带有手账记录的车票，右下角带有小书签折角或钢笔图标。
   - 点击可执行 3D 翻转动画，正面为传统火车票，背面即为该趟旅程的手账明信片。
2. **一键生成旅行长图**：
   - 支持将“正面车票 + 背面手账文字 + 照片”合并渲染生成一张复古手账长图，便于保存到系统相册或分享至社交圈。

## 3. 技术架构与数据存储设计

### 一、 数据库设计（Room 实体）

为保证架构解耦与扩展性，设计独立的 `JourneyJournalEntity`（或挂载在旅程记录表上），与 `journey_records` 表以 `journeyId` 进行 1:1 外键关联。

```kotlin
@Entity(
    tableName = "journey_journals",
    foreignKeys = [
        ForeignKey(
            entity = JourneyRecordEntity::class,
            parentColumns = ["id"],
            childColumns = ["journeyId"],
            onDelete = ForeignKey.CASCADE
        )
    ],
    indices = [
        Index(value = ["journeyId"], unique = true),
        Index(value = ["stationId"]),
        Index(value = ["createdAt"])
    ]
)
data class JourneyJournalEntity(
    @PrimaryKey
    val id: String = UUID.randomUUID().toString(),
    val journeyId: String,          // 对应的旅程ID
    val stationId: String,          // 终点站ID（用于快速检索该车站的历史手账）
    val stationName: String,        // 车站名（南京南）
    val content: String,            // 手账文本内容
    val imagePathsJson: String,     // 本地存储的图片相对路径集合 (JSON List<String>)
    val createdAt: Long,            // 创建时间戳（用于计算那年今日）
    val updatedAt: Long             // 最后修改时间戳
)
```

### 二、 图片存储安全策略
- 不在数据库直接存图片二进制 Base64，避免数据库文件膨胀导致内存卡顿；
- 用户选取的图片统一压缩保存在 App 私有文件目录：`files/journals/{journalId}/photo_0.jpg`；
- 删除手账或清除数据时，同步物理清理磁盘对应的图片文件。

### 三、 “那年今日”检索算法

检索给定目标站点 `stationId` 的历史手账：
```sql
SELECT * FROM journey_journals 
WHERE stationId = :stationId 
ORDER BY createdAt DESC
```
在内存层用 Kotlin 计算时间差：
1. 计算历史手账创建时间的月、日与当前系统时间的月、日绝对差值；
2. 若 `|month_diff| == 0` 且 `|day_diff| <= 3`，且年份差值 `year_diff >= 1`，判定为**【那年今日】**；
3. 若无严格年份差，取最近一次历史手账作为**【旧地重游】**展示。

## 4. 迭代排期规划

| 阶段 | 模块 | 核心交付物 |
| :--- | :--- | :--- |
| **第一阶段** | **数据层与手账编辑** | `UserDatabase` 迁移新增手账表、完成面板新增“记录”入口、手账文字输入与图片选择、本地持久化 |
| **第二阶段** | **车票背面翻转与长图** | 车票正反面翻转展示手账、车票+手账合并导出 PNG 分享 |
| **第三阶段** | **“那年今日”智能唤醒** | 路线选择站台时历史回忆飘带、到站完成面板“那年今日”时光卡片弹窗 |
