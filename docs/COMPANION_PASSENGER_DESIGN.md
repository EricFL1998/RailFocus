# Rail Focus 邻座同行旅客（同车次安静陪伴）设计方案

## 1. 核心理念与设计目标

### 一、 核心价值
“邻座同行旅客”旨在让单人自习的孤独感转化为“同一趟高铁车厢里，有人正与我一同向着远方默默前行”的安静陪伴感。
- **克制与不打扰**：坚决不引入嘈杂的弹幕、公开聊天室或强社交功能，保持车厢内安静专注的自习室氛围；
- **纯粹的旅伴感知**：专注期间仅在界面角落以极其克制的形式感知到“同车次旅客数”，到达终点站时共同庆祝顺利到站。

### 二、 零成本（不花钱）实现路线论证
对于个人独立开发或小成本运营的 App，购买与维护高并发云服务器、长连接 WebSocket 或即时通讯（IM）云服务会带来持续的资金与运维负担。
本项目采用 **“零服务器成本（Zero-Server Cost）/ 确定性伪实时 + 免运维免费轻量服务”** 的方案，无需花一分钱即可达到极其真实的同乘陪伴体验。

| **方案 A：高拟真时空散列算法 (纯客户端)** | 基于`日期+小时+车次/区间+全国专注活跃度模型`，纯本地确定性算法生成同乘旅伴与座位分布 | **0 元**（完全无需服务器） | 离线可用，数值极其自然，永不宕机，无延迟 | 零隐私风险，无合规压力 | **核心兜底机制（必选）** |

## 3. 详细方案设计（以推荐的混编模式为例）

### 一、 高拟真时空客流算法（纯本地零成本机制）

如果完全不使用服务器，如何让同车次人数与座位分布显得**极其真实、合乎常理且不可预测**？

1. **真实客流时间曲线（客观规律模拟）**
   - **峰谷效应**：早晚高峰（08:00~10:00，19:00~21:00）及下午黄金专注时段（14:00~16:00），基础系数提高；凌晨（01:00~06:00）基础系数调低。
   - **干线与区段热度**：京沪、京广等八纵八横主干线车次分配较高的客流基数（8 ~ 25人），短途城际分配较紧凑的客流（3 ~ 8人）。

2. **确定性伪随机种子（Deterministic Pseudo-Random）**
   - 算法种子设计：`Seed = hash(当前日期 + 当前小时 + startStationId + endStationId)`；
   - **同车共乘一致性**：只要在同一天、同一个时间段开启该区间的旅程，生成的同行旅客数量与座位分布是稳定可信的，不会在界面重组或刷新时突兀跳变。

3. **旅伴座位拟真生成**
   - 每位旅客自动分配一个符合高铁编组的座位号（如 `05车08A`、`05车08B`、`06车02C`）；
   - 自动模拟旅客进入专注的时差，部分旅客先于用户上车，部分旅客在专注中途“从途经站上车”。

### 二、 界面视觉与微交互设计

#### 1. 专注中：列车信息屏/车厢指示牌（零干扰）
- **轻量显示位置**：位于专注界面右上角控制区旁，或车窗视角小桌板上方的小电子屏。
- **UI 呈现**：
  ```
  [ 💺 同车旅客 7 人 ]
  ```
- **微交互（点击展开客流概览）**：
  - 点击胶囊弹出极简半透明磨砂面板，展示当前车厢的**“座位分布热力图”**或同乘清单：
    - `05车07F (你)`
    - `05车08A · 已专注 25m`
    - `05车09C · 已专注 40m`
    - `06车01D · 已专注 12m`
  - **绝不提供任何聊天框或打扰功能**，所有人均处于“静音专注”状态。

#### 2. 旅程中途：站台客流微感知（弱感知动态）
- 当列车驶过算法路径上的经停车站时，信息屏轻微渐变提示：
  - *“列车已通过济南西站，同车次新增 2 位旅客”*（伴随数值微调），极具长途旅行感。

#### 3. 终点到达：共同正点到站结算
- 到达终点站时，完成面板新增**【同乘纪念卡】**：
  - 展示文案：*“本次 G124 次列车共有 6 位旅客与你一同正点到达终点站”*；
  - 提供轻触互动：点击**“互致问候（静音击掌）”**，触发清脆微震动，为这次共同的坚持画上句号。

## 4. 免费云端接入方案（可选的真实数据链路）

若后续希望引入真正的全国多设备在线互通，推荐使用 **Supabase 永久免费层**（无需信用卡，不花一分钱）：

1. **极简心跳表设计（PostgreSQL）**：
   ```sql
   CREATE TABLE active_passengers (
       user_id UUID PRIMARY KEY,
       route_id TEXT NOT NULL,          -- 如 "BEIJING_SHANGHAI"
       train_number TEXT NOT NULL,      -- 如 "G124"
       start_time TIMESTAMPTZ NOT NULL,
       last_heartbeat TIMESTAMPTZ NOT NULL DEFAULT NOW()
   );
   ```
2. **零运维心跳机制**：
   - 客户端开始专注后，每隔 60 秒发送一次轻量 Ping（或更新 `last_heartbeat`）；
   - 查询同车次人数：`SELECT COUNT(*) FROM active_passengers WHERE route_id = :routeId AND last_heartbeat > NOW() - INTERVAL '90 seconds'`；
   - 免费配额每月支持 500,000 次 API 请求，对于单机专注类 App 的初始用户量绰绰有余。
